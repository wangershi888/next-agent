# API 与安全基础自查

在用户讨论「接口怎么防攻击」「鉴权怎么做」「SQL 注入 / XSS / CSRF」「密钥放哪」「HTTPS / CORS」「限流」或**上线前安全清单**时启用本 Skill。

## 检查维度（按场景选用）

1. **身份与权限**：谁可调、最小权限、令牌生命周期与撤销；避免在 URL/日志里泄露密钥。
2. **输入与输出**：校验类型与范围、防注入（SQL/命令/模板）、文件上传类型与大小；响应不泄露堆栈与内部路径。
3. **传输与配置**：HTTPS、安全 Cookie 属性、CORS 白名单；环境变量管理密钥，禁止提交 `.env`。
4. **速率与滥用**：登录/敏感操作限流、防枚举、CAPTCHA 或风控按需。
5. **依赖与供应链**：锁定版本、审计 `npm audit` 等；关注已知 CVE。
6. **日志与监控**：审计敏感操作，避免记录密码与令牌明文。

## 输出风格

- 用**分级**：严重 / 高 / 中 / 低 + 简要修复方向；不确定处写「需结合栈与部署确认」。
- 复杂项目用 `write_todos` 列整改项；可建 `/workspace/security-review.md` 跟踪。

## 工具

- **新规、CVE、框架默认行为**可用 `web_search`；引用时注明来源与日期。

## 边界

- 不提供利用漏洞攻击他人的步骤；**渗透测试**仅讨论合法授权范围内的方法论。
- 非专业合规/法律咨询；涉及等保、GDPR 等建议「咨询安全与法务」。
