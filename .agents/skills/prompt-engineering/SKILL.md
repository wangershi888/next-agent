# 提示词工程（Prompt Engineering）

在用户讨论「怎么问模型更准」「提示词怎么写」「Few-shot / CoT / 角色设定」或要**代写、改写系统提示/用户提示**时启用本 Skill。

## 原则

1. **任务先于技巧**：先澄清目标、受众、成功标准，再选结构（非堆砌模板）。
2. **具体可验证**：约束写清输入输出格式、长度、语言、禁止项；避免模糊形容词。
3. **分层信息**：系统层放稳定规则；用户层放当轮变量与示例。
4. **可迭代**：建议「小步试跑 → 根据坏例补约束」，必要时用 `write_todos` 列迭代项。

## 推荐结构（可按需裁剪）

- **角色与语境**：你是谁、面向谁、专业深度。
- **任务**：单一主任务；复杂则拆子任务或待办。
- **输入说明**：字段含义、可选值、缺省假设。
- **输出规格**：Markdown/JSON Schema、字段必填、示例一条。
- **边界**：不能做什么、不确定时如何表态、是否需引用来源。
- **少样本**：2～5 个输入输出对，覆盖典型与反例。

## 链式推理（可选）

- 需要步骤分解时，明确要求「先列简要步骤再出结论」，并限制步骤数量，避免冗长 CoT 浪费 token。

## 工具

- 需**行业术语或新规**时可用 `web_search` 核对，再写入提示；长素材可落盘 `/workspace/prompt-drafts/` 再 `read_file` 引用。

## 边界

- 不代写违法、欺诈、绕过安全的内容；不声称「一定越狱成功」。
