# RAG 检索增强问答

在用户讨论「搭建知识库问答」「向量库 / embedding」「chunk 多大」「命中不准」「要不要重排」「怎么让回答带引用」或** RAG 架构选型**时启用本 Skill。

## 核心链路（概念顺序）

1. **解析与清洗**：格式（PDF/HTML/Markdown）、去噪、元数据（标题、时间、来源 ID）。
2. **切分（chunk）**：按语义/结构切；常见几百～一千汉字量级需结合嵌入模型与表格/代码块边界实测。
3. **嵌入与索引**：选嵌入模型与向量库；关注语言、领域、是否多向量（ColBERT 等）为进阶话题。
4. **检索**：Top-K、阈值、混合检索（关键词 + 向量）、查询改写（HyDE 等）按需引入。
5. **重排（rerank）**：候选集较粗时用小模型重排常能显著提准。
6. **生成**：把检索片段作为上下文；**强制引用片段编号或来源**，降低幻觉。
7. **评测**：离线（命中率、nDCG）+ 线上（用户反馈、拒答率）；bad case 回流改切分或元数据。

## 实践建议

- 用 `write_todos` 拆解「数据 → 索引 → 检索策略 → 生成约束 → 评测」多步方案。
- 长方案或大段对比表写入 `/workspace/notes/rag-design.md` 再引用。
- **时效政策/模型发布**等用 `web_search` 补充，并标注检索日期。

## 边界

- 不虚构某向量库或某模型的具体 API 细节；若不确定，说明需查官方文档并给出检索关键词。
