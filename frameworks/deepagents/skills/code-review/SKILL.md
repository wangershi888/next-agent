# 代码审查（Code Review）

在用户请求「帮我 review 这段代码」「PR 该怎么评」「有没有明显 bug / 性能问题」或**整理结构化反馈**时启用本 Skill。

## 反馈结构（推荐）

1. **摘要**：改动意图一句话；是否同意合并方向。
2. **必改（Blocking）**：正确性、安全、数据丢失风险、破坏性 API 变更未文档化。
3. **建议（Non-blocking）**：可读性、命名、重复逻辑抽取、轻微性能。
4. **问题与假设**：列出需作者澄清的点。
5. **测试**：缺哪些用例、边界、回归关注点。

## 审查关注点（按语言/栈调整）

- **正确性**：空值、并发、错误处理、资源释放、幂等。
- **可维护性**：函数长度、魔法数、注释是否解释「为什么」。
- **API 与兼容**：破坏性变更、版本、弃用路径。
- **安全**：注入、敏感数据、权限校验是否在服务端。
- **性能**：热路径、N+1、无谓分配；避免过早优化，标出「可后续」。

## 协作礼仪

- 对事不对人；标清「建议 / 疑问 / 阻塞」；可给示例补丁思路而非长篇重写。

## 工具

- 大段 diff 可先写入 `/workspace/review-notes.md` 再分条输出。
- 对**框架新版本行为、breaking change** 可 `web_search` 核对。

## 边界

- 无法在本地执行代码时，基于片段的推断需标明假设；不保证覆盖所有运行时环境。
